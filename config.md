# Input file reference

An HRTF computation reads one required file and one optional file:

1. **the case file** (required; `config_RAY.txt` / `config_DIFF.txt`): frequencies, mesh,
   external points, output, source, normalisation, log, speed of sound. Comment
   lines (`! ...`) and value lines alternate, read in a fixed order.
2. **optionally, a technical file** (`key = value`), named on the last line of
   the case file. With `-` on that line there is no technical file and the
   default (fast) settings are used.

The step-by-step guide is [`MANUAL.md`](MANUAL.md).

File names (mesh, external points, output, log, technical file) are relative to
the directory where the solver is run, or absolute; up to 500 characters.

# Part 1 — Case file

The same file for both solvers, `config_RAY.txt` and `config_DIFF.txt`: only
line 7 (the source) differs. Comment lines (`! ...`) and value lines
alternate: value n is on line 2n of the file.

| # | Value | Example |
|---|-------|---------|
| 1 | number of frequencies `NF` (`0` with a list) | `512` |
| 2 | sampling rate `fe` (Hz) | `48000.0` |
| 3 | frequency line: one value, or the list of frequencies (Hz) | `2000.0` |
| 4 | mesh file (`.msh` or `.stl`) | `S01_R.msh` |
| 5 | external points file (Pext) | `pext_lebedev_2702.txt` |
| 6 | result file stem | `S01_R` |
| 7 | source — **Ray**: triangle number; **Diff**: point `x y z` (m) | `214178` / `0.0 -0.0625 0.0005` |
| 8 | normalisation: 1 yes, 0 no | `1` |
| 9 | verbose: 0, 1, 2 | `1` |
| 10 | log file | `S01_R.log` |
| 11 | speed of sound c (m/s), required | `340.0` |
| 12 | technical file, or `-` (default fast settings) | `-` |
| 13 | *optional* — skin impedance: `Rmax_BF Rmax_HF`, or a file; absent: rigid | `1.0 0.9` |

Diff case files written before 2026-11-20 had the skin impedance as value 9,
before the verbose: they are still accepted (the log says so).

## Number of frequencies, sampling rate, frequency line

- **Regular grid**: `NF` frequencies and a **single value** on the frequency
  line (ignored, except when `NF = 1`: it is then the frequency computed):

      f[k] = k · fe / (2 · NF),  k = 1..NF   (46.875 Hz to 24 kHz for NF = 512, fe = 48 kHz)

- **List**: several values on the frequency line (separated by spaces or
  commas), e.g. `100 500 1000 5000 10000 16000 24000`: exactly the frequencies
  computed. `NF` must be the number of values, or `0`.
- **Mixed grid** (335 frequencies, regular up to 10 kHz then 1/96 octave):
  written into the case file by `python/frequency_grid.py --mixed --config <case file>`,
  then rebuilt on 512 frequencies by `python/interpolate_hrtf.py` (see MANUAL.md).

## Mesh file

Flat triangles only:

- **`.msh`**: gmsh format 2.2, ASCII or binary (detected from the header),
  coordinates in metres;
- **`.stl`**, binary or ASCII (detected automatically). Repeated vertices are
  merged; triangles are numbered in the order of the facets. If the largest
  extent of the mesh exceeds 2, the file is taken as millimetres and converted
  to metres (message in the log).

The surface must be closed, with normals pointing **into the air**, and the head
aligned on the Oy axis (both ear canal entrances on Oy, right ear at y < 0).
Check with `python/diag_msh.py`, fix the normals with `python/msh_flip.py`.

With gmsh (https://gmsh.info): `File > Merge` to import a surface (`.stl`,
`.obj`, …), check that it is closed, then `File > Export`, *Mesh - Gmsh MSH*,
**Version 2**.

## External points file (Pext)

First line: number of points N; then N lines `x y z` (metres). Generated by
`python/generate_lebedev.py` or `python/generate_fibonacci.py`, or any set of
directions.

## Result file stem

The solver writes `<stem>.txt`. Convention: `<subject>_L` / `<subject>_R`
(`hrtf2hrir.py` derives the right-ear stem from the left one).

## Source

- **Ray**: number of the source triangle at the ear canal entrance, **from 1**,
  in the order of the triangles in the mesh file.
- **Diff**: position `x y z` (m) of the monopole, in the air near the canal
  entrance, about 2 mm from the skin (no closer than ~1 mm; no farther than
  ~3.5 mm, see MANUAL.md section 4).

`python/source_oreille.py` finds both automatically, but any triangle or point
may be chosen by hand, e.g. in a mesh viewer. **Check the numbering of the
viewer**: MeshLab, for instance, numbers the faces from 0, so add 1 to the
index it shows. A hand-picked Diff point can be checked with
`python/source_oreille.py head.msh --check x y z` (distance to the mesh, and
in the air or not).

## Normalisation

`1`: the HRTF is the pressure divided by the free-field pressure of the same
source at the head centre (head absent) — the standard HRTF definition.
`0`: raw pressure.

## Verbose

| Value | Log file |
|-------|----------|
| 0 | header (case, mesh, source, settings, octree, memory) and summary |
| 1 | + one line per frequency as it finishes: number, frequency, GMRES iterations, time — production |
| 2 | + solver details per frequency and the `CHECK` lines used by the regression tests |

Warnings (e.g. GMRES not converged) and errors are written at every level.

## Log file

Name of the log file (same stem as the results, e.g. `S01_R.log`). An empty
line writes the log to the screen. See MANUAL.md section 8 for an example.

## Speed of sound (required)

`c` in m/s, used for k = 2πf/c. Required: a silent default would change the
HRTFs without warning. Historical value of this code: `340.0`
(343 m/s in air at 20 °C).

## Technical file

Name of the technical file (part 2), or `-` for the default (fast) settings.

## Skin impedance (optional)

A locally reacting surface: one admittance β, uniform over the whole head,
function of the frequency. The line is optional (absent: rigid). For Ray, a
non-rigid skin requires `source = kreuzer` (the default); with
`source = gumerov` the program stops. Two forms:

**Two numbers** `Rmax_BF Rmax_HF`: the modulus of the reflection coefficient
varies linearly from `Rmax_BF` at 0 Hz to `Rmax_HF` at 24 kHz (fixed bounds,
whatever `fe` and the frequencies computed), with a phase of 0.17 rad
(Ghorbal et al., AES 2020); β = (1 − R)/(1 + R). `1.0 1.0` is rigid;
`1.0 0.9` follows Ghorbal et al.

**A file name**, with the skin behaviour versus frequency:

```
# my skin (comments start with # or !)
type = reflexion          # or: reflection, admittance, impedance
# f (Hz)   column 2   column 3
500        0.98       0.17
4000       0.95       0.17
16000      0.90       0.17
```

| `type` | Column 2 | Column 3 | Admittance used |
|--------|----------|----------|-----------------|
| `reflexion` | \|R\| | phase of R (rad) | β = (1 − R)/(1 + R); \|R\| ≥ 1 = rigid |
| `admittance` | Re(β) | Im(β) | β (reduced admittance ρc/Z) |
| `impedance` | Re(z) | Im(z) | β = 1/z (reduced impedance z = Z/ρc) |

Frequencies increasing; both columns are interpolated linearly; outside the
range of the file the nearest end value is used (the log says for how many
frequencies). Convention (the same as NumCalc / Mesh2HRTF): time dependence
e^{−iωt}, normal pointing into the air, ∂p/∂n = −ikβp; an absorbing skin has
Re(β) > 0. Mesh2HRTF admittances (`ADMI`) can be used as they are.

# Part 2 — Technical file

One `key = value` per line, in any order; comments after `#` or `!`; keys are
case-insensitive. Only the keys written in the file change: every **missing**
key keeps its default value. An **unknown** key stops the program (to catch
typos). No recompilation is ever needed.

## Main keys

| Key | Default | Meaning |
|-----|---------|---------|
| `reglage` | `rapide` | `rapide` (fast, for production) or `precis` (precise, reference). Read first, wherever it is in the file; the other keys then override it |
| `estimer` | 0 | `1`: print the estimated RAM per frequency and the possible number of threads, then stop without computing |
| `ram_max` | 0 | RAM (GB) allowed to the frequencies in progress; 0 = 85 % of the RAM available at start. Useful on a shared machine |
| `source` | `kreuzer` | Ray only: `kreuzer` (only the source triangle vibrates, Kreuzer et al. 2009) or `gumerov` (point source on the source triangle, Gumerov et al. 2010) |
| `iter_max` | 150 | GMRES: maximum number of iterations per frequency |

Examples:

```
reglage = precis
```

```
estimer = 1          # RAM estimate only
```

```
ram_max = 40         # leave room for other users
```

The other numerical parameters (octree, FMM accuracy per frequency band,
preconditioner, GMRES) are fixed by `reglage` to values validated against the
exact solution on spheres up to 24 kHz; they are not meant to be changed.
